## Findings (3 bugs)

### Bug A (P0) — `archiveReport` perType key mismatch (silent data loss)

**Location**: `index.html` archiveReport (cycle 16 引入)

**Repro path**:
1. 學生玩 `settings.types = ['add10']`，答對 5 次
2. `Adaptive.onCorrect` 5-streak upgrade → `settings.types = ['sub10']`
3. 學生玩 sub10 兩次都錯
4. End game → `archiveReport` 攞 `settings.types = ['sub10']` → perType 用 'sub10' 做 key
5. `add10` 嘅 5 個 correct 數據 **silently lost** 落 history snapshot

**Root cause**:
- `settings.types` 經 `Adaptive.onCorrect` upgrade 後，key migrate (`add10` → `sub10`)
- `Profile.data.statsByType` 仍 keyed by **原 typeId** (`add10`)
- perType snapshot 用 settings.types 嘅 key 攞 statsByType，key 唔 match → 升級類型嘅 learning data silently lost
- 跨 session recommendation 永遠 treat upgraded type 為 cold start → 0/0 sample → priority=3 fallback
- Mastery state 對升級路線嘅學生失真

**Family** (memory rule 13): **silent default data loss**

### Bug B (P1) — `renderRecommendChips` hardcode `'knight'`

**Location**: `index.html:2958` (cycle 16) + `topRecommendations` (line 2915, AUDIT11 carryover)

**Impact**:
- Mage 學生睇 knight 嘅 streak tiebreaker
- `Adaptive.recommendWithHistory(team, n)` 嘅 `team` param 只影響 streak tiebreaker (`this.counters[team]`)
- statsByType 係 shared 跨 team，所以 accuracy ranking 仍然 work
- 但 mastered per-team 學生 tiebreaker 唔 match current team → UX inconsistency

**Carryover**: 原 `topRecommendations` (line 2915) 都係 hardcode `'knight'`，但 comment 寫「可擴充 per-team」。Cycle 16 冇修。Cycle 17 修 `recommendWithHistory` call site，topRecommendations 留 follow-up (cycle 18+)。

**Family** (memory rule 13): **default-state desync**

### Bug E (P3) — `archiveReport` 寫 0/0 records (bloat)

**Location**: `index.html` archiveReport (cycle 16)

**Issue**: 每個 selected type 都寫入 perType entry，即使 `c=0, w=0` (例：升級後嘅 `sub10` 學生從未試過)。

**Impact**:
- HISTORY_CAP = 512KB, 50 sessions × 5 types × ~50 bytes = 12.5KB max — 唔算 bloat
- 但 0/0 records 對 cross-session accuracy 計算冇 learning value

**Family** (memory rule 13): **silent default data loss** (0/0 records 屬於 dead data)

## Fixes (cycle 17)

### Fix A — `archiveReport` 用 `Object.keys(Profile.data.statsByType)` + `c+w>0` filter

```js
// Before (cycle 16, bug):
const types = (Game.settings && Game.settings.types) || [];
for (const t of types) {
  const s = (Profile.data.statsByType || {})[t] || { c: 0, w: 0 };
  perType[t] = { c: s.c || 0, w: s.w || 0 };
}

// After (cycle 17, fix):
const statTypes = Object.keys(Profile.data.statsByType || {});
for (const t of statTypes) {
  const s = (Profile.data.statsByType || {})[t] || { c: 0, w: 0 };
  const c = s.c || 0, w = s.w || 0;
  if (c + w > 0) perType[t] = { c, w };
}
```

### Fix B — `renderRecommendChips` 用 `Game.state.currentTeam`

```js
// Before (cycle 16, hardcode):
Adaptive.recommendWithHistory('knight', 5)

// After (cycle 17, dynamic):
Adaptive.recommendWithHistory(Game.state.currentTeam || 'knight', 5)
```

### Fix E — `if (c + w > 0)` filter (包含喺 Fix A 入面)
