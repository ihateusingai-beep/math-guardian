## Why these two first

Per `.harness/docs/r1-r8-refactor-deliberation.md` 嘅 ranking：
- **Low coupling** — 兩個 function 都係 orchestration glue，唔 deep share state
- **Small diff** — 每個 ~100-150 行，可以喺一個 cycle 內 ship
- **High readability win** — orchestrator pattern 之後再加 features (e.g. cycle 13+ Adaptive.nextType 嘅 UI 整合、R1 UI monolith split) 都有清晰嘅 template

## State container 設計

setupTeacher 原本 closure 入面有 3 個 mutable variables (`removeTrap`、`escHandler`、`pauseEscHandler`)。
extract 之後用 module-scope object 包住：

```js
const _teacherModalState = { removeTrap: null, escHandler: null };
const _pauseOverlayState = { escHandler: null };
```

**點解唔直接 hoist 3 個 const/let 到 module scope？**
- 唔可以 const，因為 lifecycle 入面要 mutate
- 直接 let 會污染 global namespace，容易撞名
- 用 object container — internal field 用 `state.removeTrap` 訪問，命名 collision risk 低
- 同時 internal field 唔可被 external code 直接 mutate (除非知道 container 名)

**點解唔用 module-pattern (IIFE-returning-object)?**
- 加 complexity，但呢度只係 3 個 fields，overkill
- Plain object 更易 grep 同 audit
